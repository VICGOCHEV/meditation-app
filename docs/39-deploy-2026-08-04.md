### 0.1 Зависшие broadcast-задания

Новый воркер закрывает `pending` старше 24 часов без единой отправки как
`failed`, не рассылая. Это защита: после фикса аудитории старые задания с
нулевым охватом иначе улетели бы всем разом.

```sql
SELECT id, channel, audience, status, total_count, sent_count, failed_count,
       "createdAt", subject
FROM "BroadcastJob"
WHERE status IN ('pending', 'running')
ORDER BY id DESC;
```

Если среди них есть осмысленное — решить отдельно, досылать ли руками.
Пустой результат означает, что делать ничего не нужно.

### 0.2 Сколько строк попадёт в каждую ветку миграции 011

Выполнить **до** накатывания — колонки ещё нет, запрос её не трогает.

```sql
WITH base AS (
  SELECT u."id",
         p."enabled" AS prefs_enabled,
         s."enabled" AS sub_enabled,
         (p."userId" IS NOT NULL) AS has_prefs
  FROM "User" u
  LEFT JOIN "NotifyPrefs"  p ON p."userId"  = u."id"
  LEFT JOIN "TgSubscriber" s ON s."user_id" = u."id"
)
SELECT
  count(*) FILTER (WHERE has_prefs AND prefs_enabled)            AS "2a_перенос_вкл",
  count(*) FILTER (WHERE has_prefs AND NOT prefs_enabled)        AS "2a_перенос_выкл",
  count(*) FILTER (WHERE NOT has_prefs AND sub_enabled IS FALSE) AS "2b_stop_в_боте",
  count(*) FILTER (
    WHERE NOT has_prefs AND (sub_enabled IS NULL OR sub_enabled)
  )                                                              AS "3_дефолт_true",
  count(*)                                                       AS "всего",
  count(*) FILTER (WHERE has_prefs AND NOT prefs_enabled)
    + count(*) FILTER (WHERE NOT has_prefs AND sub_enabled IS FALSE)
                                                                 AS "останутся_выключенными"
FROM base;
```

Сумма первых четырёх колонок должна равняться `всего`. Последняя колонка —
сколько человек НЕ получат пуши после миграции, потому что отключили их сами.

## 2. Env

Добавить в `backend/.env` (полный список — в `.env.example`):

```
VPN_CHECK_PROVIDER=ipinfo
VPN_CHECK_TOKEN=<токен ipinfo>
VPN_CHECK_FLAGS=vpn,proxy,tor
VPN_CHECK_TIMEOUT_MS=3000
```

Без `VPN_CHECK_PROVIDER` гейт не сработает, даже если включить рубильник в CMS —
эндпоинт вернёт «не блокируем». Это штатное поведение, а не ошибка.

`hosting` и `relay` в `VPN_CHECK_FLAGS` намеренно не входят: под них попадают
корпоративные сети, CGNAT мобильных операторов и iCloud Private Relay.

## 4. Проверка после рестарта

```bash
journalctl -u meditation-api --since '10 minutes ago' --no-pager \
  | egrep 'meditation-api up|notifier started|broadcast worker started|push sent|push failed|broadcast|vpn gate'
```

Ожидаем `meditation-api up`, `notifier started`, `broadcast worker started` и
отсутствие стектрейсов.

**Ротация.** В ближайшую фазу дня (09:00 / 14:00 / 20:00 по таймзоне
подписчика) в логах появятся строки `push sent` с полями `phraseId`, `cycle`,
`position`, `mode`. Курсоры:

```sql
SELECT phase, count(*), min(cycle_number), max(cycle_number)
FROM "PushRotationState" GROUP BY phase;
```

**Тумблер.** Профиль → Напоминания: выключить, убедиться, что в БД
`User.notifications_enabled = false`; включить обратно — вернётся `true`, а у
привязанного подписчика `TgSubscriber.enabled` станет `true` (включение
оживляет канал после давнего `/stop`).

**TG-рассылка.** CMS → «Пуш/email рассылка» → Telegram. Сегментов
`С подпиской / Без подписки` для Telegram больше нет, охват должен совпасть с:

```sql
SELECT count(*) FROM "TgSubscriber" WHERE enabled = true;
```

Отправить тестовую рассылку на себя, дождаться тика (до минуты), проверить
`sent_count > 0` и `status = 'done'`.

**Тексты.** CMS → «Тексты приложения»: изменить текст, обновить главную в
аппке — правка видна в течение минуты (`Cache-Control: max-age=60`).
Текст правила прогрессии показывается, пока в цепочке есть хотя бы одна
закрытая практика; у пользователя, прошедшего всю цепочку, его быть не должно.

**VPN-гейт.** Рубильник в CMS → «Тексты пушей» → «Заглушка при включённом VPN».
Пока выключен, `/api/vpn-check` отвечает `{gateEnabled:false, blocked:false}` и
внешний сервис не дёргает. Включить, зайти через VPN — должна появиться
заглушка; кнопка «Продолжить без отключения» пускает внутрь.
