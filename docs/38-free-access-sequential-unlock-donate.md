# 38 — Бесплатный доступ, последовательное открытие, добровольный донат (2026-07-30)

SUPPORT-заход (billable, после сдачи 10.06). Полный отказ от платной подписки
и от обязательной оплаты внутри продукта. Повод — требования ВКонтакте к
монетизации цифровых ценностей (письмо модерации от 30.07.2026, разбор в §6).

Новая логика едина для всех платформ: отдельной механики «только для ВК» нет.
Единственное, что зависит от площадки, — показывать ли кнопку доната (§4).

## 1. Что изменилось в правилах доступа

**Было** (редакция клиента 2026-05-20):
подписка 199 ₽/мес открывает `a1`, дальше awareness открываются по четырём
условиям сразу — прошло ≥ 4 дней с прошлого открытия, предыдущая практика
прослушана, день прослушивания отмечен в трекере, а перед `a4` ещё и пройден
mid-«Глубокий анализ».

**Стало:**

1. Весь контент бесплатный. Оплата не открывает ничего.
2. Блок `relaxation` («Точка тишины») открыт целиком с первого входа,
   порядок прослушивания любой.
3. Когда прослушаны **все** практики `relaxation` — открывается первая практика
   сквозной последовательности («Пароль от жизни»).
4. Дальше по одной: прослушал текущую до конца — открылась следующая.

Сняты: 4-дневный цикл, требование отметки в трекере, гейт mid-DA перед `a4`.
Единственное условие открытия — **полное прослушивание предыдущей практики**.

«Глубокий анализ» остался самостоятельной функцией с тремя чекпоинтами
(`start` / `mid` / `final`) и больше ничего не блокирует.

### Цепочка строится из контента, а не из хардкода

Прежний `AWARENESS_ORDER = ['a1'..'a6']` убран. Последовательность собирается
из таблицы `Practice` (`block` + `order`, только `published`):

```
free     = все практики блока relaxation
sequence = awareness → awareness2 → author   (в порядке order внутри блока)
```

Это чинит давнюю дыру: второй блок «Глубже в тишину» (`awareness2`) раньше
не имел цепочки на бэке вообще, и его карточки не могли открыться никогда.
Теперь клиент добавляет практики через CMS, и цепочка продолжается сама.

Фолбэк на `r1..r3 / a1..a6` — только для пустой таблицы `Practice`
(свежая БД, локалка без сидов).

### Файлы

| Файл | Что делает |
|---|---|
| `backend/src/utils/progressionRules.js` | чистые правила: `buildChain`, `nextUnlock`, `unlockedPracticeIds`, `whichDaCheckpoint`. Без обращений к БД — поэтому покрыт юнит-тестами |
| `backend/src/utils/practiceChain.js` | `loadChain()` — читает `Practice` и отдаёт цепочку |
| `backend/src/routes/progress.js` | `GET /progress` отдаёт `unlockedPractices` = бесплатный блок + открытые из цепочки |
| `backend/src/routes/practices.js` | `POST /practices/:id/complete` считает и записывает следующее открытие |
| `backend/test/progressionRules.test.js` | 16 тестов: вход в цепочку, переходы, переход между блоками, DA-чекпоинты, легаси-юзеры |

### Совместимость со старыми юзерами

`UnlockedAwareness` не чистится и не пересчитывается. У кого практики были
открыты по подписке — остаются открытыми.

Отдельно защищён случай легаси-юзера, который вошёл в курс по подписке, но
блок `relaxation` не слушал: условие «бесплатный блок пройден» проверяется
**только для входа в цепочку** (индекс 0). Дальше по цепочке смотрим лишь на
прослушивание предыдущей практики, иначе таким юзерам откатило бы прогресс.
Покрыто тестом.

## 2. Что отключено в подписочном контуре

Код сохранён целиком — это точка отката. Отключены только точки входа.

| Что | Как |
|---|---|
| `POST /api/subscription` | отвечает `410 subscription-disabled`. Не удалён: старые закэшированные сборки клиента продолжают его дёргать и должны получить внятный ответ, а не 404 |
| `DELETE /api/subscription` | **оставлен рабочим** — у части юзеров в БД лежит `active=true` с прошлой механики, снять флаг должно быть можно |
| `POST /api/payments/yookassa/create` | `410 sales-disabled` (флаг `SALES_DISABLED` в начале файла) |
| Webhook ЮKassa | **оставлен рабочим** — надо корректно закрыть платежи, созданные до выкатки, и не потерять их в логе `Payment` |
| Авто-открытие `a1` при оплате | убрано из `payments.js` (обе ветки — webhook и 100%-промокод) и из `admin/subscriptions.js`. Оплата не открывает практики |
| `expirationNotifier` (cron) | не стартует в `index.js`. Письма «подписка заканчивается» звали бы на несуществующую оплату. Импорт оставлен, включается раскомментированием одной строки |
| Экран `/subscription`, промокоды в UI, CTA в Профиле и на главной | убраны из `routes.jsx`, `Home`, `Profile`. Файл `pages/Subscription/index.jsx` остался в репозитории |

`GET /progress` возвращает `subscription.active: true` всегда. Это намеренно:
у юзеров в localStorage лежит закэшированный `progress_state`, и старая сборка
фронта, не успевшая обновиться, иначе показала бы всё запертым.

### Пуш-фразы

`PushPhrase.audience` (`paid` / `free`) остался в схеме, но подписок больше нет —
аудитория всех подписчиков вычисляется как `free`. Фразы, заведённые клиентом
под `paid`, просто перестали бы отправляться, и в фазе без `free`-фраз пуш не
ушёл бы вовсе. Поэтому в `jobs/notifier.js` и `routes/notify.js` добавлен
фолбэк: пустая выборка по аудитории → берём любые активные фразы этой фазы.

## 3. Тексты (формулировки клиента)

**Возле заблокированной практики** (`hooks/useProgression.js`, константа
`LOCKED_HINT`, рендерится компонентом `LockedHint` на главной — только если в
секции реально есть закрытые карточки):

> Следующая практика откроется после полного прослушивания предыдущей.

**Интро-модалка перед практикой** (`pages/Player`, показывается каждый заход):

> Вы можете выбрать голос и вариант звучания. Перемотка во время практики
> недоступна. Прослушайте её до конца, чтобы завершить практику и открыть
> следующую.

**Финал практики** — «Практика завершена»:

> Спасибо, что прошли её до конца. Если эта практика была для вас полезной,
> вы можете поддержать развитие проекта добровольным донатом.
>
> Следующая практика уже доступна. *(строка показывается, только если этим
> прослушиванием реально что-то открылось — сервер возвращает `newlyUnlockedId`)*

Кнопки: **Поддержать проект** / **Продолжить без доната**.
Без доната (в VK) — одна кнопка **Продолжить**.

Ещё поправлено: подтверждение досрочной остановки говорило «не будет отмечена
в трекере», теперь — «не будет завершена и следующая практика не откроется»,
потому что теперь именно это и есть последствие.

## 4. Добровольный донат

Донат **ничего не открывает** и никак не влияет на прогресс.

Форма приёма вынесена **за пределы приложения** — отдельная страница
`https://all-relaxme.ru/donate/`, открывается во внешнем браузере. Внутри
приложения только кнопка, которая её открывает.

| Файл | Что это |
|---|---|
| `donate/index.html` | сама страница. Один файл без сборки и зависимостей, стили инлайном, единственный внешний скрипт — виджет ЮKassa |
| `deploy/donate.Caddyfile` | блок для вставки в site-блок `all-relaxme.ru` |
| `backend/src/routes/donations.js` | `POST /api/donate/create {amount}` — публичный (страница не знает про авторизацию), rate-limit 10/мин, сумма 50…30000 ₽ |
| `application/src/lib/donate.js` | `isDonateAllowed()` + `openDonate()`. В Telegram открывает через `WebApp.openLink`, иначе `window.open` |

Успешные донаты пишутся в новую таблицу `Donation` через общий webhook ЮKassa
(`metadata.kind = 'donate'`, обрабатывается до проверки `userId`/`tier`).
Отдельная таблица, а не `Payment`, потому что платёж анонимный, а в `Payment`
поле `userId` — `NOT NULL` с внешним ключом.

Миграция: `backend/sql/009_donations.sql` (идемпотентная) + модель в
`schema.prisma`.

## 5. В VK кнопки доната нет

`isDonateAllowed()` возвращает `false` для любого VK-запуска, и блок доната
не рендерится совсем.

Формально п. 5.4.1 запрещает оплату только на клиентах iOS/Android, а на
`vk.ru` / `m.vk.ru` она разрешена, и различить их можно по `vk_platform` из
launch-параметров. Но по п. 5.4.2 принимать оплату можно лишь одобренными ВК
способами, а ЮKassa в их перечень не входит — то есть разрешённого способа
оплаты у нас в ВК нет ни на одной платформе. Поэтому проще и безопаснее не
показывать донат ни в одном VK-запуске, чем разбирать платформы ради варианта,
который всё равно не пройдёт.

## 7. Что осталось за пределами кода

1. **Юридические документы.** `application/public/docs/user-agreement.pdf`
   (и, вероятно, остальные два PDF) описывают платную подписку 199 ₽/мес.
   Они открываются из Профиля, то есть находятся в «лёгкодоступном месте» —
   для повторной подачи в ВК это важно. Правит клиент/юрист.
2. **Активные оплаченные подписки в БД.** Люди оплатили месяц, а контент стал
   бесплатным. Возвраты не делались — это решение клиента, не техническое.
   Прогресс у таких юзеров не откатывается (§1).
3. **Количество практик в стартовом блоке.** ТЗ говорит «четыре стандартные
   практики». Цепочка считается по контенту: первая практика «Пароля от жизни»
   откроется после прослушивания **всех** опубликованных практик блока
   `relaxation`. Перед выкаткой стоит убедиться на проде, что их там ровно
   четыре и все `published`.
4. **Ссылка на страницу доната.** По умолчанию `https://all-relaxme.ru/donate/`,
   переопределяется `VITE_DONATE_URL`.

## 8. Деплой

Обычная zero-downtime последовательность (`AGENTS.md`) плюс два новых шага.

```bash
ssh med-prod
cd /opt/meditation-app
git pull --ff-only

# 1. НОВОЕ: миграция таблицы донатов (идемпотентная)
psql -U <user> -d meditation_app -f backend/sql/009_donations.sql

cd backend && npm install && npx prisma generate
cd ../application && npm run build
cd ../cms && npm run build
# лендинг НЕ билдить — на проде заглушка, build:landing её затрёт

# 2. НОВОЕ: страница доната. Сборки не требует, лежит как есть.
#    Добавить блок из deploy/donate.Caddyfile внутрь site-блока all-relaxme.ru
#    (выше общего fallback-а статики фронта), затем:
caddy validate --config /etc/caddy/Caddyfile && systemctl reload caddy

systemctl restart meditation-api
```

Проверить после выкатки:

- `curl -sI https://all-relaxme.ru/donate/` → 200
- `curl -s -X POST https://all-relaxme.ru/api/subscription -H 'Authorization: Bearer …'` → 410
- новый юзер: блок «Точка тишины» открыт целиком, «Пароль от жизни» закрыт
  с подсказкой; после прослушивания всех стартовых практик открывается первая
- юзер со старой подпиской: ранее открытые практики остались открытыми
